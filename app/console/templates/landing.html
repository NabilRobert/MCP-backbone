  1. Ask a question. Claude explores the schema, then runs one read-only query.
  2. Try to change data. The server refuses anything but a single SELECT.
  3. Check what ran. Every query, including refused ones, shows up in your audit trail.

How it stays safe

  • Read-only in three layers: the SQL is parsed and checked, every transaction runs READ ONLY, and the database login itself can't write.
  • Cost-checked: expensive queries are rejected before they run, and results are capped.
  • Limited: each API key has only the tools it needs, and per-hour rate limits.
  • Audited: every attempt is logged before an answer is returned.
